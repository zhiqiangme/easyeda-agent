# 设计流程：原理图数据到实物版图

本文件只规定阶段产物和验收边界。原理图数据及转换命令读
[schematic-data.md](./schematic-data.md)；器件选型与典型外围电路查器件数据手册；
PCB 操作分别读 [pcb-layout.md](./pcb-layout.md) 和 [pcb-routing.md](./pcb-routing.md)。

## 开始与恢复

- 按用户当前目标切入：已有原理图修复不必重做整板方案，原理图任务不自动扩展为 PCB。
- 沿用已确认的器件、接口、机械约束、装配工艺和操作授权。只有缺失信息会改变设计或超出授权时才询问；用户要求逐步确认时遵守其节奏。
- 新任务先核对目标工程、页面和现有文件；连接异常按 [environment-setup.md](./environment-setup.md) 处理。变更命令指定 `--project` 和 `--doc`。
- PCB 恢复用 `easyeda workflow status --reconcile` 对照实况，再按 `easyeda workflow advance` 的下一步继续。已有状态不能代替当前几何校验。
- 每个已验证检查点显式 `sch save` 或 `pcb save`，检查保存结果。daemon 的默认 3 秒防抖 autosave 是补充；重启或关闭编辑器前先保存。

## 原理图 S0–S6

当前主线是 **本地 Connectivity IR → Lib 局部几何 → compose → sch apply → 回读对账**。
缺失或非法位号才按官方库前缀分配；已有合法位号保留。不要把布局变化写成器件或网络身份变化；功能名放 `role`。

### S0 — 明确需求和数据来源

记录供电、接口、电气要求、板框/装配约束，以及尚未实现的需求。按功能划分 Lib：
核心器件及其去耦、上下拉、滤波、时钟等外围属于同一模块。旧工程中的缺失外围先在
本地 IR 中补齐；不要通过散放器件、换标签来掩盖不完整的电路。

选型使用官方器件库身份、引脚表和数据手册典型电路。若已有 spec，保持它的模块清单、
接口引用与 IR 的稳定 ID 对齐；未实现需求单独标明，不能把历史位号当作当前清单重放。
`easyeda spec validate <file>` 可检查方案书结构，不能证明引脚连接正确。

### S1 — 建立可信快照与纸张边界

读取当前连接关系，保存本地基线；补齐器件库身份、实测 bbox、引脚位置及已有导线，
再准备目标数据。恢复既有工程时保留原器件 ID、引脚编号、网络 ID 和 NC 意图。

用 `sch sheet-geometry --json` 确认纸张与图签禁放区，注意输出的测量/推导来源。
默认 A4，先评估单页容量；按功能决定必要的分页。`sch compose` 只合成一页，
不会自动分页、缩放符号或删除源页。不能靠缩小图签禁放区或无限外扩坐标塞下模块。
纸张数据缺失时可继续离线准备，实际落图前必须取得可信边界。

### S2 — 分配位号并完成模块数据

存在缺失或非标准位号时，按 [schematic-data.md](./schematic-data.md) 使用 `sch designators allocate`，
从官方库测得的前缀分配缺失编号，保留已有合法位号及声明顺序。编号后同步本地模块、
接口、placement、terminal 的引用；仅修位号时用 `sch designators plan/verify`，
不重新计算布局或重建电路。

稳定 ID 是查找器件的依据，不能从 ID 截取位号，也不能用角色名拼装位号。
引脚连接和 NC 必须在本地数据中可检查，再进入几何规划。

### S3 — 计算放置、导线和模块框

先放核心，再依据引脚方向放外围，模块内部优先直接短导线。供电/GND 可重复使用
标记；端子信号优先水平直出、按文字占用错开引线长度。不得为避碰改变电气网络。
布局与呈现细节见 [schematic-placement.md](./schematic-placement.md)。

Lib 内部几何由本地计算生成；`compose` 不从裸网表生成外围位置和接线。保留计算输入、
脚本与参数，先重跑并核对不变量，再交给组合器。已有完整模块几何可以直接复用。

`sch compose` 离线计算模块范围、标题空档和从左上开始的 Z 字行布局；同一行等高，
页边距与模块间距由当前算法固定为 10 raw（0.1 inch）。标题为 20 raw（0.2 inch），
采用粉色虚线模块框；本版本不要求 Notes。纸张或模块放不下时修改数据与功能分组，
不要通过反复落图试摆或放宽碰撞判据来推进。

器件本体 bbox 不一定包含外置位号、型号等文字。已测文字范围应进入障碍数据；
缺少这些范围时，离线几何通过仍需在最终原生图中核对穿字、遮挡和线端方向。

### S4 — 编译与执行 SCH Apply

用新鲜的目标页快照编译可检查的队列，先运行 `sch apply <file> --dry-run`。
只有任务授权替换既有页面内容时才用 compose 的 `--replace`；已有明确授权不再重复询问。

执行 `sch apply <file>`，由队列依次派发并等待响应，保留 journal。`--yes` 可落实已获
授权的队列确认，不扩大操作范围。放置后先核对实际器件身份、引脚和几何，再连线；
不要绕过生成队列中的断言。

写请求超时或报错时先检查 journal 和回读结果，区分未执行、已落地与部分完成。
含连接守卫或 `requireFullExecution:true` 的队列必须重新生成并完整执行，不能用
`--resume/--from/--to` 跳过守卫；只有允许续跑的普通队列才按 journal 使用 `--resume`。
不能不看实况重复创建或删除。

### S5 — 回读验证

1. 导出新的 `sch connectivity`，用 `sch connectivity-diff` 对照目标 IR；确认器件、
   引脚、网络和 NC 一致。跨页工程同时检查完整网络关系，不能只验当前页。
2. 完整原理图验收对受影响页面运行 `sch gate --strict --json`。它按
   `layout-lint → check → bridge-check → drc` 执行，严格模式把间距、孤儿桩等告警
   也列为阻塞。局部诊断可按需使用普通 gate，但不能称为严格过门。逐页切到前台执行，
   `--all-pages` 的非活动页几何较浅，不能替代逐页严格检查。
3. `fail` 是设计问题，`blocked` 是检查未完成；均不能报告验收通过。已有报告包含
   各检查明细，不必无变化地重复跑每条检查。对仍存在的 advisory 明确说明影响。

官方 DRC 不能覆盖全部数据或呈现问题。网表对账、导线树检查、文字/框线核对各有范围，
不能用其中一项通过代替全部结论。

### S6 — 修复、保存和交付

依据具体 finding 修改本地目标数据，重新计算受影响差异并 Apply，再验证相关不变量。
保存最终原理图并确认成功，交付目标 JSON、计划/队列、回读结果与仍未解决的事项。
需要展示效果时用 `sch export-image` 导出当前原生图；数据绘图应标明来源，不能代替
原生截图或运行时验收。只有目标包含 PCB 时才继续下列流程。

## PCB P0–P10

PCB 沿用实际阶段门，详细参数以当前 `--help` 为准。布局、板框或布线修改会失效
相应下游确认；`workflow status --reconcile` 能发现 GUI 等外部变更带来的指纹漂移。
确认命令记录已经审阅的结果和用户决定，不要求对未改变的已授权内容再次提问，
也不能把未审阅的布局写成用户签核。

| 阶段 | 工作与检查点 |
|---|---|
| P0 新建/选择板 | 用 `pcb board-info` 核实原理图与 Board 关联；已有板直接使用。`pcb new-board` 用于未绑定原理图，不为普通更新迁走现有原理图。 |
| P1 导入 | `pcb import-changes` 同步原理图，按其实际 UI 反馈完成导入；`pcb add-component` 是逐件放置入口。回读器件身份、位号、焊盘网络，导入完成后保存。 |
| P2 放置 | 从 spec 读取装配工艺、单/双面、机械及接口要求；实测 bbox/pads 后放置，并按下文分档记录。 |
| P3 板框 | 有机械约束时先建约束板框；无尺寸约束时粗布局后收紧板框。检查安装孔、垫圈、连接器开口及焊盘是否落在合法范围，再记录 `pcb stage confirm-outline`。 |
| P4 禁布 | 在布线前落实天线、RF、安装及开槽禁布区；依据 spec/器件手册决定层与范围。 |
| P5 丝印占位 | `pcb silk-align` 校正位号，预留装配后可见的接口和极性文字空间。 |
| P6 布线前门 | 最终板框上运行 `pcb layout-lint --gate`；通过后才取得 `pre_route_passed`。 |
| P7 布线 | 先关键网、后普通信号，按下文选择布线方式；不要跨越阶段门。 |
| P8 电源与铺铜 | 按已确定的叠层/电源策略完成铜面、缝合和回流；修改后重建铺铜并验证。 |
| P9 标注 | 核对接口逐脚标记、极性、板名版本；文字在器件本体外且装配后可见。 |
| P10 终检 | `pcb drc --json`、`pcb check`，完成 `post_route_checked` 门，再 `pcb save`。报告残余告警；送板或外部交付遵循已有授权范围。 |

### 放置与阶段门

装配工艺确定后用 `pcb stage set-assembly` 持久化。当前手焊 profile 的普通器件间距
下限为 40 mil，大焊盘烙铁通道默认 60 mil；回流焊用 `reflow` profile。
电气 clearance 不能替代装配可达性。未知工艺且影响封装/布局时再向用户确认。

按孔/结构件 → 边缘接口 → 主芯片与 RF → 卫星件顺序完成四档。用
`pcb stage confirm-tier <1|2|3|4>` 记录成员；空档用 `--empty`，第 4 档可覆盖剩余件。
接口边序与开口方向依用户机械需求确定，已确认的方向可直接落档。主芯片和外围的
贴脚距离遵循手册，RF/天线净空不能拿来填充小器件。

`pcb floorplan --spec <file>` 可先规划功能带，`pcb place-constrained` 与
`pcb auto-place` 执行相应放置；这些工具不能替代机械意图。完成四档、实测检查后记录
`pcb stage confirm-layout`，最终板框确认后重跑 P6。

`pcb layout-lint --gate` 要求装配 profile、无重叠/出板框/过紧间距，并满足当前分数与
交叉数阈值。`pcb layout-score` 用于质量诊断，不自动成为另一道门；其中 skipped
表示未测。不要为了过门调低安全要求；`--force`/`--force-unsafe` 是有审计的越门选项，
不作为正常恢复步骤，也不写入阶段确认。

### 布线、电源与工艺

- 布线前核对真实叠层、网络类别、差分/等长预算和禁布区。线宽、过孔、间距以项目
  实时 DRC 规则和 [fab-rules-jlcpcb.json](./fab-rules-jlcpcb.json) 工艺下限为依据；
  数据手册的电流、阻抗、回流与散热要求不能由工具默认值替代。
- `pcb route-critical --spec <S0.json> --dry-run` 先核对真实铜层与需求，再检查关键网方案；
  层数无证据或与 `stackup.layers` 不符时拒绝执行，不默认两层。执行后确认电源铜、差分线
  长度与锁定状态。差分预算以本板接口规范为准，不把某个样例的 skew 数字推广到所有网。
- 稀疏短连线可用 `pcb route-short`；它默认跳过电源/GND。稠密板采用用户选定的原生
  自动布线或已配置外部路由器。`pcb autoroute` 需要外部 engine，无配置时只导出 DSN；
  导出数据必须包含禁布区。不要把外部路由器当成已存在的官方无弹窗 API。
- 原生自动布线前保留已有导线/过孔、保护已完成的关键网；若内层专用于电源/地，
  普通信号不要占用那些层。UI 确实需要人工且现有工具无法操作时，再交回这一步。
- 电源走线宽度按网络电流与规则计算；铜面选择按层数和网络隔离确定。两层可用
  `pcb power-pour`；四层 `pcb power-planes` 默认 GND 在层 15（内电层）、电源在层 16。
  多电源轨不要短接在同一平面；局部铜和零散轨单独处理。
  `power-planes` 保持已有四层及以上叠层；两层升级须有已确认需求并显式传
  `--allow-stackup-change`，未知层数始终拒绝。dry-run 同样预检并列明是否计划升级。
- `power-planes` 已封装 SIGNAL 上建网络铜 → 转 GND PLANE → rebuild 的顺序。
  铜面或 via 修改后检查 anti-pad、热连接、EP 接地与散热要求，不能因命令成功就判连通。
- PCB 写后按 `STALE_READ` 提示用 `doc reload` 刷新；铜形变化后 `pcb pour-rebuild`。
  同网断连先复核重建后的数据。DRC 需活动前台，超时先查运行状态，不并发重复发检查。
- `pcb beautify` 是可选呈现处理，先 dry-run；处理后仍需 DRC、连通与关键网长度复核。
  布线修改会重置 `post_route_checked`，重新过门后才能交付。

## 验证范围与留档

只读/离线验证不要求打开编辑器，但不能声称已完成原生 API、DRC 或落盘验收。
运行时失败保留输入、响应和 journal，以可复现差异定位问题；已通过且未改变的步骤不重复跑。

本仓库完整端到端回归按 `AGENTS.md` 使用 `esp32MiniRequire.md` 第一节原始需求作为
输入，在 `ceshi` 测试工程走完对应 S/P 阶段，不能喂预制 BOM/UUID/网表代替选型验证。
该要求适用于完整回归，不把普通文档修改或局部用户修复扩成整板任务。完整回归记录
`easyeda audit cost` 成本台账；录制/演示需要原生阶段图时再用 `pcb stage-snapshot`。
